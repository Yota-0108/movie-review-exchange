# デプロイ前タスク分担表

映画感想ランダム交換システムの構築において、「Claude Codeが書ける部分(コード化できる)」と「人間が実際にAWS環境に対して行う必要がある操作」を分けて整理する。

前提:IaC(AWS CDK)を採用する。TypeScriptで書けるため、Reactで使う言語知識をそのまま流用でき、学習コストも抑えられる。

---

## Claude Codeが書ける部分(コード化できる)

- **CDKスタック本体**:Aurora Serverless v2、Lambda関数、API Gateway(HTTP API + JWT Authorizer)、Cognitoユーザープール、S3バケット、CloudFrontディストリビューション(マルチオリジン構成)、IAMロール/ポリシー、Secrets Managerの参照設定
- **Lambda関数のコード**:各APIエンドポイントの処理ロジック
- **DBスキーマ定義・マイグレーションスクリプト**
- **Reactフロントエンドのコード**
- **films/tagsの初期データをINSERTするスクリプト**(データそのものの収集は別途必要)
- **テストコード**

---

## 人間が実際に行う必要がある作業

| 作業 | 理由 |
|---|---|
| AWSアカウント作成・支払い方法の登録 | 個人の契約行為そのもの |
| ローカル環境へのAWS認証情報(IAMユーザーのアクセスキー等)の設定 | 認証情報の管理は本人の責任範囲 |
| `cdk bootstrap`の実行 | アカウント全体に影響するIAMロール・S3バケットを初回作成する操作。実行者が意図して行うべき |
| `cdk deploy`の実行(特に初回・IAM変更を含む変更) | 実際に課金が発生し、IAM権限が変わる操作。差分(diff)を確認した上で人が実行判断すべき |
| AWS Budgets(予算アラート)の設定 | 「想定外の高額請求を防ぐ」という設計思想を運用面で徹底するための人的な安全策 |
| 独自ドメインを使う場合のドメイン購入・Route 53への登録 | 外部registrarとの契約、DNS委任は人が行う契約行為 |
| ACM証明書の発行申請・DNS検証レコードの確認(us-east-1リージョン) | CloudFront用証明書はus-east-1での発行が必須。DNS検証用レコードがRoute 53に正しく反映されたかの確認は人的チェックが望ましい |
| コスト監視ツールの使い分け(初期モニタリング) | 3つを目的別に使い分ける。①**CloudWatch**:システムの稼働状況・ログを見る(Lambda実行回数・エラー率、API Gatewayレイテンシ等)。②**Cost Explorer**:実際に何にいくら使ったかをサービス別・日別で振り返る(デプロイ初期の1〜2週間はこまめに確認し、想定外の費用増加に早期に気づく)。③**AWS Budgets**:「月◯◯円を超えたら通知」という先回りの予算アラートを設定する。3つとも無料で使える |
| Cognitoのメール送信設定の動作確認(確認コードが実際に届くか、迷惑メール判定されないか) | 実際のメール到達性はコードでは検証できない |
| デプロイ後のセキュリティ最終確認(Public access無効化の実際の確認、Secrets Managerのローテーション設定等) | 「コードで意図した設定」と「実際に反映された設定」が一致しているかの人的レビュー |
| 脆弱性チェックツールの導入・実行(`npm audit`、cdk-nag、IAM Access Analyzer。必要に応じてAmazon Inspector) | サーバーレス構成のため、EC2/コンテナ向けのInspector単体では不十分。cdk-nagでデプロイ前のインフラ設定ミス検出、npm auditで依存パッケージの脆弱性、IAM Access Analyzerで過剰な権限の検出を組み合わせる。継続監視が必要ならInspectorも追加検討 |
| films初期データの収集(興行収入ランキングの実データ確認) | Web検索で実データを確認する作業。AIに直接生成させず、実データを確認したうえで変換作業のみAIに任せる方針のため |

---

## 切り分けの基準
- **繰り返し可能・再現性が必要なもの** → コード化してClaude Codeに任せる
- **一度きり・アカウント固有・お金や契約が絡むもの** → 人間が実行・承認する
